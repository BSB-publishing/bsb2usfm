# Paratext Adaptations — Lossy Changes

The script `adapt_usfm_for_paratext.py` modifies USFM files generated by
`bsb2usfm.py` to pass Paratext's Basic Checks validation. Several of these
adaptations are **lossy** — they remove or alter information that is present
in the original BSB data. The unmodified files under `results/` retain the
full original content.

This document describes each lossy adaptation and what is lost.

## Lossy Adaptations

### 1. `\ref` markers converted to plain text

**What changes:** Custom `\ref` markers with machine-readable link targets
are converted to plain text.

**Example:**
```
Before: \ref John 1:1-5|JHN 1:1-5\ref*
After:  John 1:1-5
```

**What is lost:** The machine-readable reference target (e.g., `JHN 1:1-5`)
is discarded. The human-readable display text is preserved. Paratext does
not support the custom `\ref` marker.

### 2. `\wj` markers removed (Words of Jesus)

**What changes:** `\wj ... \wj*` markers that identify the spoken words of
Jesus are removed. The text content is preserved.

**Example:**
```
Before: \wj I am the way, the truth, and the life.\wj*
After:  I am the way, the truth, and the life.
```

**What is lost:** The red-letter distinction for Jesus' spoken words.
Bibles that display Jesus' words in red will no longer be able to do so
from the Paratext-adapted files. This is necessary because `\wj` markers
in the BSB frequently span across verse and paragraph boundaries, causing
Paratext to generate `<unmatched marker="wj*" />` validation errors in
USX output.

### 3. `\r` parallel passage references removed

**What changes:** Entire `\r` lines containing parallel passage
cross-references are removed.

**Example:**
```
Before:
\s1 The Creation
\r (John 1:1-5; Hebrews 11:1-3)
\p \v 1 In the beginning...

After:
\s1 The Creation
\p \v 1 In the beginning...
```

**What is lost:** All section-level cross-references to parallel passages
(e.g., parallel Gospel accounts, OT/NT connections). The `\r` marker is
valid USFM, but Paratext flags the verse ranges within these references as
"Invalid end range" errors because they appear at the section heading level
before any verse marker. There is no suitable alternative marker: `\sr` is
semantically different (it marks the section's own scripture range), and
`\x` belongs inside verse text.

### 4. `\mt2` + empty `\mt1` collapsed to `\mt1`

**What changes:** The `\mt2 BookName` line followed by an empty `\mt1`
line is collapsed into a single `\mt1 BookName` line.

**Example:**
```
Before:
\mt2 Genesis
\mt1
\c 1

After:
\mt1 Genesis
\c 1
```

**What is lost:** The two-level major title hierarchy (`\mt2` + `\mt1`)
is replaced by a single `\mt1`. This is necessary because the empty
`\mt1` causes an "empty marker" error, and removing it entirely leaves
only `\mt2`, which Paratext rejects because DBL requires a `\mt` or
`\mt1` marker before chapter 1.

### 5. Empty `\q1` and `\p` lines removed

**What changes:** Standalone `\q1` or `\p` lines that contain no text are
removed.

**What is lost:** Visual spacing/separation between text blocks. These
empty paragraph markers act as separators in the original files but
Paratext flags them as empty marker errors.

### 6. `\pmo` converted to `\p`

**What changes:** `\pmo` (embedded text opening) markers are converted to
standard `\p` (paragraph) markers.

**What is lost:** The semantic distinction of `\pmo` as an embedded/
continuation paragraph style. Paratext flags `\pmo` as "Marker cannot
occur here" in certain list contexts (e.g., summary totals after list
items in Numbers 2).

### 7. `\mr` converted to `\d`

**What changes:** `\mr` (major section reference range) markers are
converted to `\d` (descriptive title) markers.

**Example:**
```
Before: \mr For the choirmaster. With stringed instruments.
After:  \d For the choirmaster. With stringed instruments.
```

**What is lost:** The semantic distinction between a section reference
range and a descriptive title. This affects only Habakkuk 3:19 where
`\mr` appears at the end of the book. Paratext flags `\mr` as "Marker
cannot occur here" in this position.

## Non-Lossy Adaptations

The following adaptations fix formatting issues without losing information:

- **Strong's number padding:** Numbers are zero-padded to 5 digits
  (e.g., `H776` becomes `H00776`). No information is lost.
- **Trailing empty `\ft` removed:** Empty `\ft` markers before `\f*` at
  the end of footnotes are removed. No content is lost.
- **Empty `\fqa` before `\fv` removed:** Empty `\fqa` markers that
  immediately precede `\fv` verse number markers in footnotes are removed.
  No content is lost.

## Remaining Paratext Warnings

The following warnings are **not addressed** by this script because they
are intentional or require Paratext project configuration:

- **"#Verse missing"** — Certain verses (e.g., Matthew 17:21, Mark 7:16)
  are intentionally omitted in the BSB because they follow the critical
  text. The omitted verses are noted in footnotes. A `custom.vrs` file under `sfm_for_paratext/`
  is provided that lists these as excluded verses so Paratext accepts
  the intentional omissions.
- **"seed-bearing" non-wordforming characters** — Hyphenated compound
  words inside `\w` markers. This is a Paratext project setting issue
  (configure hyphen as word-forming character).

### Quotation Check Warnings

Paratext's Quotation Check may report thousands of warnings (including
"Unexpected quotation mark value" for every quote in the text). These are
**not** problems with the USFM text — the BSB uses standard English
typographic quotation marks correctly. The warnings occur because the
Paratext project's Quotation Rules have not been configured. Follow the
steps below to resolve them.

#### Step 1 — Configure Quote Marks

Open **Project menu** (`≡`) > **Project Settings** > **Quotation Rules**
and enter the following values (you must be a project Administrator):

| | Opening | Closing | Continuer |
|---|---|---|---|
| **Level 1** | `"` (U+201C) | `"` (U+201D) | `"` (U+201C) |
| **Level 2** | `'` (U+2018) | `'` (U+2019) | `'` (U+2018) |
| **Level 3** | `"` (U+201C) | `"` (U+201D) | `"` (U+201C) |

The **continuer** is the mark placed at the start of a new paragraph when
a quotation carries over from the previous paragraph. In English the
continuer is the same character as the opener.

**Tip:** Copy and paste the characters from the table above directly into
the Paratext dialog fields rather than trying to type them from the
keyboard.

#### Step 2 — Configure Apostrophe as Word-Medial Punctuation

The right single quotation mark `'` (U+2019) serves double duty in
English: as a closing single quote and as an apostrophe (e.g., "don't",
"Israel's"). Without this step Paratext flags every apostrophe as an
unexpected closing quote.

Open **Project menu** (`≡`) > **Language Settings** > **Other Characters**
tab and add the following to the **Word-medial punctuation** field:

- `'` (U+2019, right single quotation mark / apostrophe)
- `-` (hyphen, for compound words like "seed-bearing")

#### Step 3 — Re-run the Quotation Check

Go to **Checking** > **Run Basic Checks**, select **Quotations**, and run
the check. The vast majority of the previous warnings should now be
resolved. Any remaining warnings are genuine quotation issues worth
reviewing individually.
